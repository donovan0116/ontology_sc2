# Ontology SC2 Agent V0.1 设计

## 目标与边界

V0.1 使用 Terran 最小规则跑通 BurnySc2 的观察、决策、动作、结果、日志、指标、
回放和批量实验链路。它不实现分层 Manager、本体、RDF/OWL 或知识图谱。

## 选型

采用 `burnysc2==7.3.0`（安装包名 `burnysc2`、导入名 `sc2`）和 Python 3.11。
配置用标准库 dataclass 加 PyYAML 严格解析，避免为少量配置引入 Pydantic。
规则策略保持纯函数式、只消费可序列化领域快照；SC2 对象只存在于适配器和执行器。

## 边界与数据流

`BotAI` 观察由 bot 适配成 `GameSnapshot`，`TacticalAdvisor` 返回有优先级的
`MacroIntent`，执行器把宏观意图翻译为 BurnySc2 命令。每次决策和执行结果写入
JSONL，聚合器生成每局 JSON 指标。运行器负责路径、回放参数、失败持久化和批次汇总。

## 规则与资源冲突

策略可以同时返回资源无关动作和宏观生产动作。候选意图先去重、再按优先级排序，
并用当前矿物和人口进行保守预算，避免同一步过度承诺。`pending_actions` 阻止重复
建造和重复训练。首次攻击后不再反复向全军提交相同命令。

## 错误处理与测试

短暂条件不足返回 `waiting`，前置条件不满足返回 `rejected`，找不到工人、位置或
目标等操作失败返回 `failed`。运行器是允许捕获未知异常的进程边界，并必须先写
`error.json` 和失败指标再决定是否继续。领域、配置、策略、日志、指标和批次逻辑
不实例化真实 SC2 客户端；真实对局测试仅在 `RUN_SC2_INTEGRATION=1` 时启用。
